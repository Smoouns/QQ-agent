# 聊天窗口与记忆召回

聊天设置中的「聊天窗口」默认从最近 80 条历史开始，后续保持窗口头不动，历史增长到 120 条后，下一次超过上限时裁回最近 80 条；另加本次全部新消息。窗口与 @、关键词、随机响应滑条独立。可以设置 0–500 条，并按会话覆盖，例如 `group:123456=100`、`private:123456=60`。后端配置字段为 `store.historyCount`、`store.chatHistoryCounts`。

## 存档与窗口

- 原有规范化聊天存档完整保留。旧 `maxMessagesPerChat` 配置不再裁剪消息；已被旧版本删除的消息无法恢复。窗口、分页、记忆抽取只读，不压缩、不按天清理历史。
- 转发展开仍更新可读文本，同时用 `originalText` 保留展开前文本。这里保留的是原系统规范化消息及媒体定位信息，不是完整 OneBot 原始事件或媒体永久副本。
- 运行开始、任何异步请求之前固定本地消息 ID 上界。历史首次取触发批之前最近 N 条允许访问的消息，随后沿用窗口起点，超过 `ceil(N × 1.5)` 条才裁回最近 N 条；先过滤屏蔽名单再计数，新消息全部保留。N 为 0 时不带历史。两部分按本地 ID 排序并显示完整日期、QQ 身份、QQ 消息 ID 和分页用的 local ID。
- 上一轮机器人回复可能夹在本批未读消息之间，这些已经发出的消息也按顺序带入。能够按引用 ID 在本会话存档中定位的窗口外消息单独补充并去重；旧记录只有引用摘要时保留摘要，不按名字猜测身份。
- 本轮开始后到达的新消息留在未读队列，下次运行处理。成功结束才确认本批；不回应的触发批直接确认。最终失败且没有尝试副作用时保留未读，可手动唤醒或等待新消息再次触发。不会对同一失败批次无限自动重试。
- 已尝试发送、记忆写入等副作用或 MCP 调用时，失败不自动重放整批，以避免结果不确定时重复操作。此保护不是跨进程崩溃的严格一次执行保证。

`get_recent_messages` 默认读取提示词历史窗口之前的消息，返回 `nextBeforeLocalId`、`hasMore`。下一页传 `beforeLocalId`，不受新增消息影响。兼容 `offset`，但它相对于固定边界。指定消息、图片、来源和活跃成员的工具也遵守本轮边界与屏蔽名单。

### 群成员查询

`get_group_members` 仅在群聊向模型开放，通过 OneBot `get_group_member_list` 查询当前群，包括没有发言记录的人。模型不能传入其他群号。仅返回 QQ 号 `userId`、昵称 `nickname`、群名片 `card`。

- `query`：按 QQ 号、昵称、群名片包含匹配，英文忽略大小写；同名保留多个候选。
- `userId`：精确 QQ 号字符串。
- `limit`：默认 20，范围 1–100。
- `afterUserId`：用上一页 `nextAfterUserId` 继续查询，保持原查询条件不变。

结果包含 `total`、`count`、`members`、`hasMore`、`nextAfterUserId`。本轮首次查询缓存完整名单，按 QQ 号稳定排序分页；下一轮重新获取。缓存只存在运行期内存，不将完整名单写入会话或提示词。屏蔽名单在网络返回后及每次分页时重新过滤，接口失败允许重试。`get_active_members` 仍用于查询聊天存档中的活跃成员。

## 自动召回

先检查当前会话可见范围、有效状态及屏蔽名单，再评分。QQ 全局身份本身不扩大范围；通过稳定个人资料校验的群聊称呼、长期兴趣和交流习惯可跨会话召回，私聊与具体经历保持原范围。共享资料参与当前人物一路的召回，即使没有话题词命中，也可在原来的条数预算内选取。分类及迁移规则见 [记忆设计](memory-v2.md#稳定个人资料与旧记忆迁移)。

1. 人物路线最多 3 条：以新消息发送者、结构化 @ 和被引用者为主体，选择相关事实、偏好、关系，以及称呼、相处习惯。窗口里的路过成员不会各自自动带三条印象。
2. 话题路线最多 5 条：新消息词项优先，最近 8 条历史和引用作为辅助。共同事件只出现一次；内容相同且主体相同的记录去重。相关的待办与进行中事项加权，完成经历仍可召回；固定记录也需要相关。
3. 最多 8 条，不强行填满。中文使用本地分词并补充被拆开的双字词；优先新消息匹配，其次背景话题、人物、状态，更新时间作为同分排序项。

召回条目带 ID、版本、主体、类型、状态和证据标签。只注入当前有效版本。需要回忆修改前的约定时，模型可用 `memory_query(recordId, includeHistory: true)` 获取仍然可见的旧版本。

`memory_query` 支持 `query`、`userId`、`eventId`、`recordId`。列表默认 20 条、最多 50 条，同时按工具文字上限整条分页；后续将 `nextOffset` 传为 `offset`。指定 ID 可展开原始证据和历史，证据原文仅返回当前会话来源，历史版本单独检查可见范围。详情过大时返回明确错误，可关闭 includeHistory 或提高工具文字上限，不输出半截 JSON。

`memory_person_query` 是显式跨会话人物查询入口，必填 `userId`（真实 QQ 号）。它返回该人物在所有群聊、私聊及全局范围中的有效事实、偏好、互动、关系、事件和承诺，不要求话题命中，不受来源会话可见性限制，仍检查有效性、证据和当前会话屏蔽名单。此工具默认供普通聊天使用，也可在权限设置中限制或禁用。

默认只返回 `{ "memories": ["喜欢策略游戏", "[他人转述] 喜欢咖啡", "[待完成] 测试新功能"], "nextOffset": null }`。正文完整保留，不额外调用模型摘要或机械截断；仅转述、推测、缺少原始证据及待完成／进行中／已完成／已取消状态添加标记，必要的事件标题合并到正文。省略 ID、版本、时间、范围、数量和固定说明等常规回答用不到的信息。完全重复的条目先去重，再分页；正文、证据、状态、类型、标题、主体和关联事件须相同，避免合并不同事件或冲突内容。

`limit` 默认 10、最多 50；从 `offset: 0` 开始，把非 null 的 `nextOffset` 传给下一页，null 表示结束。按更新时间倒序、同时间按 ID 排序；后台更新时分页顺序可能变化。需要定位、编辑或排查记录时传 `detail: true`，返回 `{ "records": [...], "nextOffset": ... }`：每条包含 ID、正文、类型、状态、证据、版本，并按需附标题、多人主体、关联事件或固定标记；不返回来源原文、昵称或历史版本。详细模式保留重复记录以便逐条处理，与简洁模式使用不同的分页列表；切换模式须从 offset=0 重新查询。两种模式均不输出 total/count/hasMore 或重复说明。

显式查询以目标 `personId` 单独跟踪已读取版本，后续模型请求和发送可继续使用这些跨会话结果，不会因原会话范围不匹配而中断；记录删除、失效、移出目标人物或屏蔽变化仍使运行停止。普通召回及 `memory_query` 的访问跟踪不获得这个例外，查询工具也不修改记录原范围、共享分类或其他会话原始聊天的访问权限。

两种记忆列表同时遵守 `runLimits.toolResultMaxChars`（默认 6000 字符），按实际紧凑 JSON 的长度计算，包括转义、字段、兼容投影及游标；页可能少于 limit，下一页偏移按实际返回条数推进。Agent 工具使用本轮固定的文字上限，避免设置变化导致外层再次截断。单条记忆本身放不下时返回结构化错误、`blockedOffset`、`requiredMaxChars` 和 `maxChars`，不跳过该条、不推进游标、不把未返回内容登记为已读取；提高上限或改用简洁模式后，从 blockedOffset 继续。工具正文和游标均不机械截断。

这是本地词项与人物规则召回，没有新增模型调用、向量数据库、摘要或压缩。不同措辞、隐含指代和纯语义相似可能漏召回；可由模型换词搜索或按人物/事件展开。后续可替换评分层接入 embedding，身份与权限检查仍由本项目执行。

## 稳定组装与诊断

系统消息包含角色、行为和工具规则，不含当前时间、活跃管理员名单或手动测试标记。私聊默认每批回应的策略只由会话种类和响应设置决定。工具按名称稳定排序，权限与可用性变化仍会更新实际提供的工具。

用户消息按以下顺序组装：

1. 固定会话标识及机器人 QQ。
2. 统一的聊天记录：历史、新消息、期间已发送的机器人消息按 local ID 排序，全部使用同一种格式。不写已读状态或本轮临时触发标签，新消息只追加到记录末尾。
3. 动态尾部：当前时间、已核验管理员交互风格、会话状态、召回记忆、窗口外引用、表情包目录、本轮待处理的 local ID、可选手动测试要求。新消息正文不重复粘贴。

窗口锚点仅保存在进程内，按 store 和会话隔离；重启、基础条数变更、屏蔽名单变化或回退到更早边界时重建。它不修改存档。消息原文被转发展开更新、成员备注或人设被修改、权限和工具列表改变时，相关前缀可能变化，这是正常的内容更新。

初始窗口和记忆在运行开始时选定。初始提示词只组装一次，整轮重试复用同一输入。当前运行的工具调用及对应结果继续追加；下一次运行重新构造两条初始消息，不携带此前工具输出。机器人真正发到 QQ 的消息仍从聊天存档进入后续窗口。

每次常规模型请求前，在末尾追加一条运行预算快照，包含剩余模型/工具次数、搜索分类额度、累计输入、时间和无进展计数；不会修改先前快照或插入固定前缀中。收尾阶段同样在末尾追加可用工具与预留次数提示。会话详情和 JSON 模式可查看这些运行期提示，下一次独立运行不携带旧快照。

单次请求容量独立于累计输入预算：`maxContextTokens` 默认 65536，`contextReserveTokens` 默认 4096。每次 HTTP 前检查消息、工具定义、调用参数和图片估算；输入估值超过总容量减输出预留时不发送请求，聊天进入 `context_capacity` 收尾。收尾会先删除多余旧预算提示，再按时间顺序移除较早工具正文及工具图片（留下明确占位说明，保持 tool_call/result 配对），不剪裁初始系统规则或聊天文本。仍然超限则本地记录错误停止，不反复发同一超限请求。详见 [运行预算与收尾](run-budgets.md#单次请求容量)。

管理员改变屏蔽名单，或已使用的记忆被删除、失效、收紧到当前会话不可见时，停止后续模型请求和工具使用；发送队列在每条消息真正发出前再检查。已提交给模型的请求及已发出的消息不能追溯撤回。

会话详情的「上下文选取」展示消息边界、基础/最大历史条数、本轮是否裁剪、历史/新消息/引用 ID、分页游标和召回记忆的 ID、版本、选择原因；JSON 模式包含相同信息。

### 缓存统计

- 每次模型响应记录缓存字段是否被明确报告；缺失不是零。兼容 `prompt_tokens_details.cached_tokens`、`input_tokens_details.cached_tokens`、`prompt_cache_hit_tokens`、`cached_tokens`、`total_cached_tokens`。
- 用量页、分组和下钻没有数据时显示「未报告」；有部分报告时，分母只包含已报告调用的输入 token，明确标记「部分」。旧聚合记录中程序填充的 `cachedTokens: 0` 无法证明接口曾报告，因此按未知处理；原始响应可用时优先重算。
- 用量页单独展示每次运行首次请求和工具续轮的命中率。只有旧聚合数据而没有逐轮响应时列为未知轮次，不猜测分摊。新运行保存 `usageByPhase`。
- 未报告缓存的输入按未命中价格估算，不能据此断言实际账单。前缀稳定只改善复用条件，缓存有效期、最小长度、路由以及是否返回计数仍由模型服务和转发端决定。
