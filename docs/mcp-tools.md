# 添加 MCP 工具

入口：**设置 → 工具（MCP）**。原有 QQ、搜索、记忆工具保持原来的使用方式，外部 MCP 工具与它们一起提供给聊天模型。

## 使用流程

1. 点击「添加服务」，填写名称及连接信息。
2. 点击「保存并发现工具」。这一步会启动本机程序或连接远程地址，但不会调用发现的业务工具。
3. 勾选需要的工具，打开「允许机器人使用此服务中勾选的工具」。新服务和新发现的工具默认关闭。
4. 选择适用聊天：所有机器人白名单内聊天，或指定 `group:群号` / `private:QQ号`。指定列表为空表示不授权任何聊天。
5. 点击「保存设置与工具选择」。下一次聊天运行会加载这些工具；不用重启 QQ Agent。
6. 可展开「参数格式」，点击「填写参数试调用」，输入 JSON 参数及白名单内的聊天。试调用会真实执行工具，使用已保存的服务、工具和聊天权限。

只勾选工具但未打开服务开关，或者勾选后没有保存，都不会让机器人获得调用权限。删除服务或变更配置会关闭旧连接；已经发出的外部动作不能撤回。

## 本机程序：stdio

根据 MCP 服务作者提供的启动说明填写：

| 字段 | 示例与说明 |
|---|---|
| 启动程序 | `node`、`npx`、`uvx` 或程序绝对路径；不要把整条命令填在这里 |
| 启动参数 | JSON 字符串数组，例如 `["D:/services/my-server.mjs"]` |
| 工作目录 | 可选的绝对路径 |
| 环境变量 | JSON 对象，例如 `{"MY_API_KEY":"你的密钥"}` |

启动采用独立程序和参数数组，不额外开启 shell。Windows 下隐藏子进程窗口；SDK 负责常见命令查找。Node.js、Python 或服务要求的其他运行环境，需要在电脑上可用。

程序继承 SDK 的基础环境变量（例如 PATH、TEMP），不会继承 QQ Agent 进程中的所有密钥。服务需要的环境变量在这里显式配置。服务程序以当前系统账户权限运行，聊天适用范围不是文件系统沙箱；文件访问范围应同时在服务自身配置。

## URL：Streamable HTTP

- 填写实际 MCP 端点，例如 `http://127.0.0.1:8000/mcp` 或服务商提供的 HTTPS 地址。
- 静态认证通过请求头填写，例如 `{"Authorization":"Bearer 你的令牌"}`。
- 允许管理员明确配置本机／局域网服务；连接拒绝 HTTP 重定向。地址需要变更时直接编辑服务 URL。
- 本版不支持旧版 HTTP+SSE 端点、OAuth 登录流程或客户端证书配置。

环境变量和请求头保存在本机 `data/config.json`，普通配置接口及管理页面不回显值，只显示已保存的键名。编辑时留空会保留已有值，输入对象会整体替换，填写 `{}` 会清空。不要把密钥放在名称、启动参数或 URL 中。分发脱敏脚本会移除整个 MCP 服务配置列表。

## 调用行为和限制

- 工具名称自动加服务标识及哈希，避免不同服务、特殊字符和内置工具之间重名。
- 调用前按服务的 JSON Schema 校验参数。无法编译的输入 Schema 会显示错误并禁止启用；不会因此禁用同一服务的其他可用工具。
- 同时遵守机器人白名单、黑名单、服务开关、工具勾选以及服务的适用聊天范围，执行前重新检查权限。
- 默认超时 30 秒，单次文本结果上限 8,000 字符，可分别修改。连接和分页发现共享一个超时期限。
- 本版向模型传递文本、嵌入资源的文本、资源链接描述及结构化 JSON。图片、音频和二进制资源会提示暂不支持，不会自动下载资源链接。
- 服务连接按需建立并复用；连接失败会在会话反馈中显示，其他工具仍能使用。自动连接失败后冷却 30 秒，控制台「保存并发现工具」可主动重试。
- 外部工具调用不自动重试，因为超时后服务仍可能已经执行了动作。尝试过 MCP 工具的会话，也不再整轮从头重试；后续单个模型请求仍可按原策略重试。
- 工具调用记录进入原有会话详情和工具用量统计。手动试调用只在当前页面展示结果，不制造 QQ 聊天会话。
- 最多配置 16 个服务、每个服务发现 256 个工具；一次聊天最多提供 64 个已启用的 MCP 工具，超过时在会话反馈中提示。工具会按稳定名称排序后取前 64 个。
- 不向服务开放 sampling、elicitation、prompts 或自动读取 resources。本版也不提供 MCP 任务扩展的异步作业交互。
- 不自动向 MCP 服务发送聊天历史、QQ 凭据或完整上下文；工具收到模型生成的调用参数。模型仍可能在参数中引用当前聊天内容，启用工具时应考虑其实际访问的数据和执行动作。

## 本地验证

在项目根目录运行：

```powershell
npm run test:mcp
npm test
```

MCP 测试创建本地 stdio / HTTP 服务和模型桩，验证协议握手、分页、作用范围、配置热修改、参数校验、超时、返回截断、凭据脱敏、子进程关闭、HTTP 管理接口，以及完整聊天调用与失败重试行为。测试使用临时目录，不调用真实 QQ 或真实模型。

也可以打开隔离的控制台预览：

```powershell
node test/mcp-preview.mjs
```

打开终端输出的本机 URL，进入「工具（MCP）」并选择「本地演示（测试用）」。发现工具后勾选 `find.item`、开启服务、保存，试调用聊天填 `group:1`，参数填 `{"text":"你好"}`。预期返回 `echo:你好` 和结构化测试信息。此预览使用单独的临时数据，不启动 OneBot；终端按 Ctrl+C 会关闭连接并清理临时目录。

正式使用可运行 `npm run server` 打开浏览器控制台，或在安装好 Electron 桌面运行依赖后运行 `npm start`。

## 实现位置

- `src/mcp.js`：配置校验、MCP 连接、发现、授权及工具适配。
- `src/app.js`：`/api/mcp/servers` 管理接口及退出清理。
- `src/orchestrator.js`：为当前聊天加载工具，记录调用，限制整轮重试。
- `ui/app.js`：MCP 设置和试调用页面。
- `test/mcp-test.mjs` / `test/fixtures/mcp-server.mjs`：独立协议与聊天集成验证。

协议适配使用 [官方 TypeScript SDK](https://github.com/modelcontextprotocol/typescript-sdk/tree/v1.x)，对应 [客户端文档](https://github.com/modelcontextprotocol/typescript-sdk/blob/v1.x/docs/client.md)。
