# OpenCodex 搜索

QQ Agent 保留现有 Chat Completions 聊天链路，将 `web_search` 的执行后端切换为独立 Responses 请求。OpenCodex 负责登录凭据、订阅路由和上游转发；本项目不会读取其账号文件、登录令牌或管理令牌。

## 使用

1. 启动 OpenCodex 并完成账号登录。
2. 在「设置 → 搜索服务」选择「OpenCodex 原生联网搜索」。
3. 填写接口基址（默认 `http://127.0.0.1:10100/v1`，也接受完整 `/v1/responses` 地址）、搜索模型（默认 `gpt-6-luna`）和超时（默认 120 秒）。
4. 未启用本机接口鉴权时，搜索 Key 留空即可。已有 Key 可勾选「清除已保存的搜索 Key」清除；留空或保留掩码不覆盖旧 Key。
5. 保存，再输入测试查询并点击「测试已保存的搜索服务」。测试始终使用已保存配置，消耗搜索额度，不启动聊天 Agent 或向 QQ 发消息。

出厂默认仍为 Bing；切换搜索提供方不修改聊天模型、记忆或响应规则。OpenCodex 设置只配置搜索本身，不修改代理配置。

## 协议与结果

- 请求 `POST /v1/responses`，声明 `tools: [{ type: 'web_search' }]`、`tool_choice: 'required'`，请求搜索来源。
- 使用 `store: false`、`stream: true`、低推理强度，不添加订阅后端不接受的 `max_output_tokens`。每次只发送当前查询，不发送 QQ 聊天记录、人设或记忆。
- 同时兼容 SSE 和 JSON。SSE 按事件收集正文、完成的搜索调用和引用；最终快照缺少 `output` 时使用之前收到的内容，不丢弃代理的有效结果。
- 必须收到正常完成状态、至少一次真实 `web_search_call` 完成，以及有效的结构化来源链接。普通模型文本、同名函数调用、未完成调用均不算搜索成功。
- 来源优先采用 `url_citation`，补充搜索动作返回的来源；正文中自行写出的 URL 不作为已验证的结构化来源。来源列表可能同时包含引用页和检索候选页，不表示每个页面都支持全部总结。
- 总结属于搜索模型生成的辅助文本，不能当作网页原文或系统指令；聊天模型可用 `web_fetch` 进一步核实，并保留支持结论的来源链接。
- 限制响应体为 2 MiB、总结为 6000 字符、来源为最多 10 条（服从 `webSearch.maxResults`）。来源 URL 去除 `utm_*` 跟踪参数后去重。
- 超时涵盖连接和响应体读取；测试连接关闭时取消请求。HTTP 失败、流中断、无搜索证据或无来源会明确报错，不重试、不自动回退其他搜索服务。

搜索子请求的 `usage` 保留在工具结果中。当前聊天 token/费用统计不会自动合并该子请求；订阅剩余额度以 OpenCodex/官方账号状态为准。控制台手动搜索测试不进入聊天会话用量。

## 验证

```powershell
npm run test:search
npm run test:render
```

自动化测试使用临时数据目录和本地模拟服务，不访问订阅或真实 QQ。覆盖代理空最终快照、分块 UTF-8/CRLF、引用恢复、无搜索证据、错误/截断、大小上限、超时取消、密钥脱敏、控制台测试及保存行为。

2026-10-28 在本机 OpenCodex 2.73.0 + `gpt-6-luna` 做了两次最小在线验证。首次确认真实搜索和引用事件；第二次通过本适配器完成检索，约 9 秒返回 `AbortSignal.timeout(delay)` 的单位说明及 Node.js 官方来源。此结果确认链路可用，不代表所有查询的搜索质量或延迟保证。
