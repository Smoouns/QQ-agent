# 群聊响应规则

聊天设置默认使用确定的热聊 / 冷场 / 累计消息保底规则，覆盖所有**允许接入**的群聊，不会扩大白名单。私聊默认沿用原响应档位，不参与自动参与统计。旧的概率冷场开话题不再运行，旧 `proactive` 配置不再决定行为。

## 默认条件

| 项目 | 默认值 |
| --- | --- |
| 多人热聊 | 滚动 60 秒内至少 2 人、共 6 条消息 |
| 单人连发 | 同一窗口中同一人至少 5 条；设为 0 可关闭 |
| 热聊聚批 | 达标后等待 2 秒空隙；从首次达标起最多等待 15 秒 |
| 冷场接话 | 最后是人的消息，120 秒没有新消息 |
| 累计保底 | 累计 20 条普通消息未触发模型，不受热聊时间窗口限制；设为 0 可关闭 |
| 自动参与额度 | 每群滚动 60 秒内最多 2 次 |
| 自动参与冷却 | 两次自动模型运行至少相隔 20 秒 |

三个触发器共享额度。保底与热聊一样，达标后等待 2 秒空隙、最多等待 15 秒；同时命中只运行一次。达到条件代表给模型一次判断机会，不保证发言。一次自动运行在第一次模型请求前扣额度，即使模型保持沉默或请求失败也计入；同次运行的工具轮次和原有失败重试不重复扣额度，因此这不是每分钟 HTTP 请求数或 token 的硬上限。

明确的 @、引用回复机器人、关键词和管理员命令不占自动参与额度，仍受原有并发、权限及发送约束。普通群聊采用规则模式时，不再使用原随机滑条决定是否响应；关键词表继续共用。

## 不重复接话

- 新的人类消息重置冷场计时；机器人的实际发言清除此前的候选。
- 同一段静默只给一次机会，模型不发言也不会定时反复调用。
- 已用于模型判断的消息退出本轮热度累计。未达到条件而被标记已读的消息仍可在统计窗口内累计，不受聊天已读游标影响。
- 冷却、额度不足、并发已满时跳过当前自动候选，不排队等待额度恢复。只有后续新消息会建立新候选。
- 保底计数跨已读批次和热聊窗口累计，仅计正常入站消息，内部只保留有界消息元数据。实际开始模型处理（包括 @ 等明确触发）或机器人发言后清除此前累计；限流跳过保留累计，但不会在没有新消息时重试。暂停、修改规则、失去接入资格和重启时清除。
- 命令、屏蔽消息、机器人的发言不增加热度；图片等正常消息按一条计数，不分析语义。
- 规则变化、暂停或会话失去接入资格会取消候选；模型请求前再次检查自动触发条件。
- 原始聊天不删除，继续使用现有历史窗口。已读消息触发冷场时，最后一条人类消息作为本次输入，即使历史窗口设为 0 也不会丢失触发内容。

活动统计、冷场标记和额度保存在进程内，重启后清零；旧存档不会自动启动冷场接话。新消息到达后开始统计。定时检查间隔约 1 秒，实际开始时间还受事件循环和模型可用性影响。

## 每个会话单独调整

在「聊天设置 → 单独调整会话」选择或输入 `group:群号` / `private:QQ号`，添加设置，最后点击保存。留空字段继承默认值，移除单独设置后恢复继承。

- 群聊可选：热聊 / 冷场 / 保底规则、仅 @ / 关键词、每批调用模型、旧档位。
- 私聊可选：仅 @ / 关键词、每批调用模型、旧档位；不能启用群聊自动触发器。
- 群聊可单独设置热聊、冷场与保底的开关或阈值，以及共享冷却和每分钟额度。
- 保底通过 `fallbackMessages` 调整，可全局或逐群设为 15、20 等条数，0 为关闭。
- 旧档位模式可为任意会话单独设置滑条位置；未填写时沿用原统一 / 分群档位设置。

配置存于 `responseRules`；`responseRules.chats` 以会话键索引覆盖项。默认组使用 `groupMode`，覆盖项使用 `mode`，数值由后端限制在可用范围。原 `store.contextTier` 等字段保留，仅旧档位模式使用。

设置页显示最近触发 / 跳过原因，运行记录保存 `responseDecision` 与自动额度扣除标记，可区分规则判定、实际模型调用与最终 QQ 发言。

## 验证

`npm run test:response` 使用隔离目录、可控时间和本地模拟模型，验证热聊、冷场、额度、覆盖、取消、聚批计时及编排器实际调用，不连接真实 QQ 或付费模型。原响应档位的兼容测试继续保留。
