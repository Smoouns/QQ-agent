# QQ Agent

运行在本地电脑上的 QQ 群聊与私聊机器人，提供 Electron 桌面端和浏览器控制台，通过 OneBot v11 收发消息，接入 OpenAI 兼容模型 API。

本仓库基于 **[K0nd1us/QQ-agent](https://github.com/K0nd1us/QQ-agent)** 进行二次开发，主要改进工具扩展、统一 QQ 身份记忆、上下文组装、管理员权限与群聊响应规则，并移除了原作者服务的数据上报和推广入口。

## 当前功能

| 功能 | 说明 |
| --- | --- |
| QQ 互动 | 文字、引用回复、@、表情包、戳一戳，以及当前群成员查询 |
| 群聊自动参与 | 根据热聊、冷场和累计消息保底规则决定是否唤醒模型，支持逐会话调整 |
| 统一人物记忆 | 按 QQ 号关联跨群与私聊身份，记录事实、偏好、关系、事件和承诺，保留来源与版本 |
| 上下文管理 | 固定本轮消息边界，组装最近历史、当前新消息、引用与可见记忆；完整聊天存档保留 |
| 外部工具 | 支持本机 stdio 和 Streamable HTTP MCP 服务，按工具及会话授权 |
| 管理员命令 | 按真实发送者 QQ 校验权限，支持调用限流、参数规则和可选确认 |
| 本机状态 | 管理员发送 `/电脑状态`，查看 CPU、内存、磁盘、运行时间及 NVIDIA GPU 利用率与显存 |
| 搜索与图片 | 支持 OpenCodex 原生联网搜索、多种搜索服务和自定义配置；图片处理取决于模型能力与视觉设置 |
| 运行记录 | 查看提示词、模型输出、工具调用、实际发言、token 用量和费用估算 |

## 安装与启动

源码运行需要 Node.js 20 或以上版本及 npm。桌面端主要面向 Windows；QQ 登录由单独的 OneBot 协议端负责。

1. 在项目目录运行 `npm install` 安装依赖。
2. 准备 OneBot v11 协议端。可自行安装 SnowLuma 并放在项目根目录的 `snowluma` 文件夹，也可使用其他兼容实现，在设置中填写其连接地址和令牌。SnowLuma 为独立第三方项目，不随本仓库分发。
3. 运行 `npm start` 启动桌面端。安装依赖后，也可双击 `启动QQ机器人.bat`。
4. 在控制台配置模型服务的 Base URL、API Key 和模型，连接协议端并完成 QQ 登录，设置允许接入的群聊与私聊。
5. 如需使用管理员工具，在「设置 → 权限与命令」填写自己的 QQ 号并保存，然后发送 `/权限` 检查身份。

```powershell
npm install          # 安装依赖
npm start            # Electron 桌面端
npm run server       # 仅启动服务，使用浏览器控制台
```

浏览器控制台默认地址为 `http://127.0.0.1:3210`，实际端口以启动输出为准。

## 群聊如何决定回应

默认对所有允许接入的群聊启用以下规则，**不会自动扩大接入白名单**：

| 规则 | 默认条件 |
| --- | --- |
| 热聊参与 | 最近 **1 分钟**内至少 2 人共 6 条消息，或同一人累计 5 条 |
| 冷场接话 | 最后一条是人的消息，之后 **120 秒**没有新消息 |
| 累计保底 | 累计 **20 条**普通消息未触发模型，不受热聊时间窗口限制 |
| 聚批等待 | 热聊或保底达标后等待 2 秒空隙；持续发言时最多等待 15 秒 |
| 共享额度 | 每群滚动 **60 秒最多自动参与 2 次**，两次至少间隔 20 秒 |

达到条件表示给模型一次判断机会，模型仍可以选择不发言。额度按自动模型运行计算，即使模型沉默也会扣除；同一次运行的工具轮次和失败重试不重复计数，因此它不是 token 或 HTTP 请求数的硬上限。

- @、引用回复机器人、关键词和管理员命令不占自动参与额度，仍受各自的处理与权限规则约束。
- 冷场不会周期性重复触发。保底被限流时保留累计，等新消息到来再判断，不排队延迟补发。
- 未触发的消息会标记已处理，原始记录继续保留。
- **私聊不使用上述自动参与规则**，默认沿用原响应档位。
- 「聊天设置 → 单独调整会话」可覆盖每个群聊或私聊的响应方式。群聊可以调整阈值、关闭触发器，或切回旧档位；保底可设为 15、20 等条数，0 表示关闭。

旧档位保留为兼容模式：仅 @、@ 加关键词、再加随机概率、每批调用模型。选择旧档位时才使用对应滑条。

测试时可在「存档」中选择一个群聊或私聊，点击 **测试 Agent 回复**，立即跳过自动触发规则调用模型。没有未读消息时使用最近一条可见用户消息，回复会发到当前 QQ 会话；暂停、接入范围、工具权限及发送限制仍然生效。运行结果在「会话」页查看。

详细配置、取消条件与运行期状态说明见 [群聊响应规则](docs/response-rules.md)。

## OpenCodex 联网搜索

若聊天模型通过本机 [OpenCodex](https://github.com/lidge-jun/opencodex) 使用官方订阅，可在「设置 → 搜索服务」选择 **OpenCodex 原生联网搜索**。默认接口地址为 `http://127.0.0.1:10100/v1`，搜索模型为 `gpt-6-luna`，超时 120 秒。接口 Key 仅在 OpenCodex 开启接口鉴权时填写；搜索不会读取订阅登录令牌，也不自动沿用聊天服务的 Key。

保存后点击 **测试已保存的搜索服务**，可输入自己的查询，查看耗时、搜索调用证据、总结和来源。测试会使用订阅额度，但不会发 QQ 消息。聊天模型与人设不变，只有调用 `web_search` 时才向 OpenCodex 发起独立检索请求。

适配器要求真实搜索完成且返回来源链接；连接中断、模型只凭已有知识回答等情况会显示失败，不会自动回退到 Bing。新安装仍默认使用 Bing，已有配置也不会被自动替换。详见 [OpenCodex 搜索说明](docs/opencodex-search.md)。

网页抓取支持完整 Markdown 链接，并兼容代理的 `198.18.x.x` Fake-IP DNS：自动查询真实公网地址后校验并连接，继续阻止内网访问。兼容方式、关闭开关及脚本渲染限制见 [网页抓取说明](docs/web-fetch.md)。

## 图片发送与生图

Agent 可用 `send_image` 发送公网图片直链，也可用 `generate_image` 文生图或图生图，再按返回的图片 ID 发送。支持“`web_search` 找网页 → `get_webpage_images` 提取图片 → `import_image` 导入 → `inspect_image` 看图 → `generate_image` 按文字和参考图生成 → `send_image` 发送”。也能从当前会话消息中导入图片，最多使用 4 张参考图。网页提取仅支持静态 HTML，动态网站可能没有可用候选。默认接入本机 OpenCodex 的生图接口，生图模型由上游选择，与聊天模型独立。

在「设置 → 图片与生图」可调整接口、尺寸、画质和预算。默认**每个群聊／私聊每天 5 次**，文生图和图生图共用额度，北京时间零点重置；支持单会话覆盖，0 次表示禁用。预算按请求尝试计算，失败或超时也扣次；导入、查看和重发已有图片不扣生图次数，重启不清零。图片保存在本地，ID 只能用于原会话。详见 [图片与生图说明](docs/images.md)。

## 记忆与上下文

### 按 QQ 号统一身份，按范围控制可见性

同一个 QQ 号在不同群聊和私聊中关联同一个人物实体。记忆可以关联一个或多个人，包含事实、偏好、互动、关系、事件和承诺，并保存来源消息、证据类别、状态及修改历史。

**统一人物不等于自动公开私聊内容。** 自动抽取默认保持来源会话范围，管理员可将适合共享的记录调整为全局或指定会话可见。控制台支持查看、编辑、固定、逻辑删除及检查历史版本。

机器人普通发言不会自动变成长期人设事实；有来源支持的共同事件、明确承诺可以保留。记忆抽取独立于聊天响应运行，所以没有触发聊天模型不代表后台记忆处理也没有模型费用。

详见 [记忆设计与迁移](docs/memory-v2.md)。

### 滑动窗口与完整存档分开

每轮运行重新组装系统提示词与本次上下文，包含最近历史、当前新消息、引用和本轮选中的可见记忆。历史默认取最近 **80 条**，支持逐会话覆盖，与响应档位无关。

当前运行中的工具调用及结果会继续用于后续模型轮次；下一次独立运行不再携带之前的工具输出。机器人实际发到 QQ 的内容仍保留在聊天存档中，可进入后续历史窗口。运行期间到达的新消息留给下一轮处理。

窗口不会自动删除或压缩原始聊天记录。它限制了常规历史输入，但当前新消息、记忆、图片和本轮工具结果仍会影响 token 用量，**单轮成本不是固定值**。

详见 [上下文组装与记忆召回](docs/context-v3.md)。

## 工具扩展与权限

### MCP 外部工具

在「设置 → 工具（MCP）」添加本机 stdio 或 Streamable HTTP 服务，发现工具后，勾选工具、启用服务并选择适用会话。新服务与新发现的工具默认不向机器人开放。

连接、参数与结果有相应检查；本机 MCP 程序仍以当前系统账户运行，会话授权不等于文件系统沙箱。工具页面的试调用会实际执行工具。

配置示例与当前支持范围见 [MCP 工具说明](docs/mcp-tools.md)。

### 管理员直接命令

管理员身份按 OneBot 入站消息的真实 QQ 号判断；QQ群主或群管理员身份不会自动获得机器人管理员权限。管理员风格设置只影响交流方式，不扩大工具权限或记忆可见范围。

| 命令 | 作用 |
| --- | --- |
| `/帮助` | 查看本人可用的命令 |
| `/权限` | 查看本人是否为机器人管理员 |
| `/电脑状态` | 管理员只读查看本机运行指标，无参数 |
| `/确认 编号`、`/取消 编号` | 处理需要确认的操作 |
| `/命令名 {"参数":"值"}` | 调用控制台注册的工具命令 |

直接命令由程序解析，不经过聊天模型。受限工具需要明确的命令授权，管理员普通聊天不会让模型自动获得这些权限。

`/电脑状态` 默认每分钟最多调用 3 次，采集前后及发送前检查权限。GPU 指标通过本机 NVIDIA 驱动的 `nvidia-smi` 获取；不支持或读取失败时显示暂不可用，不影响其他状态项。

命令注册、限流、会话范围、参数规则与可选确认见 [权限与命令说明](docs/permissions.md)。

## 控制台与运行方式

- **会话**：查看每轮输入、模型输出、工具调用、上下文选取依据、实际发言和错误。
- **存档**：按群聊或私聊浏览完整消息与已读状态。
- **记忆**：按人物、事件和会话管理记录，检查来源、版本与后台抽取进度。
- **用量**：按时间、会话、模型等维度查看 token 与费用估算；价格可配置，实际账单以服务商为准。
- **设置**：管理模型、MCP、人设、接入范围、响应规则、权限、发送节奏和桌面选项。

协议层使用 OneBot v11，模型层使用 OpenAI 兼容接口；模型服务需支持所用的工具调用能力，视觉能力另行配置。桌面壳使用 Electron，控制台使用原生 HTML/CSS/JavaScript。

## 数据与联网

聊天存档、记忆、会话记录和用量默认保存在本地 `data/` 目录，可通过 `QQ_AGENT_DATA_DIR` 指定数据目录。

本分支已移除意见收集、金句上传、作者网站与群入口、自动用量遥测、作者版本检查，以及遗留 DSH 配置读取代码。版权信息与开源致谢继续保留。

模型、搜索、MCP 和 QQ 协议端仍会按配置联网；调用模型时，选中的消息、记忆与工具结果会发送到所配置的模型服务。远程价格表仅在用户配置 URL 后启用。本地存储不意味着所有推理都在本机完成。

审查范围、移除项和第三方组件边界见 [联网审查记录](docs/privacy-audit.md)。

## 开发与验证

```powershell
npm test                  # 全部回归
npm run test:response     # 热聊、冷场、保底、额度与会话覆盖
npm run test:manual       # 手动 Agent 回复接口与权限
npm run test:search       # OpenCodex 搜索、来源验证和设置接口
npm run test:fetch        # 网页抓取、Fake-IP DNS 兼容和内网拦截
npm run test:images       # 图片发送、生图接口和每日会话预算
npm run test:computer     # 本机状态、GPU 与管理员权限
npm run test:mcp          # MCP 连接与调用
npm run test:memory       # 记忆、来源与版本
npm run test:context      # 上下文窗口与召回边界
npm run test:permissions  # 权限与直接命令
npm run test:privacy      # 已移除的上报与上传路径
```

测试使用隔离数据目录和模拟服务；电脑状态测试包含真实本机只读采样。测试通过不代表已经验证真实群聊中的回答质量、记忆准确性或所有 OneBot 实现的兼容性。

分享部署副本前，可先预览分发脱敏操作，再按需执行：

```powershell
node scripts/sanitize-release.mjs --dry-run
node scripts/sanitize-release.mjs
```

脱敏脚本会清理密钥、授权配置、存档和登录态等部署数据，应在准备分发的副本上使用。
